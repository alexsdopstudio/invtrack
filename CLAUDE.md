# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal stock-research dashboard: aggregates **free public data** (official senate EFD disclosures, SEC EDGAR Form 4 insider trades, yfinance fundamentals/prices) into a composite 0–100 score with full provenance, plus a quantitative screener and an opt-in paid Claude 10-K analysis. Core product rules: **never give buy/sell advice** (persistent disclaimer everywhere), **every number must be explainable** (per-component breakdowns, raw payloads stored, data timestamps), and **everything except the AI analysis stays free/keyless**.

## Commands

```bash
# Backend (Python 3.11+, FastAPI)
cd backend
./setup.sh                                  # venv + deps + alembic upgrade head; pins pip to public PyPI (ignores corporate indexes)
.venv/bin/python -m pytest tests -q         # all tests
.venv/bin/python -m pytest tests/test_scoring.py::test_congress_cluster_bonus -q   # single test
.venv/bin/python -m app.cli seed-demo       # synthetic demo data, no network needed
.venv/bin/python -m app.cli ingest all      # live ingestion (also: tickers|congress|insider|fundamentals|prices), then rescores
.venv/bin/uvicorn app.main:app --reload --port 8000
.venv/bin/alembic revision --autogenerate -m "..." && .venv/bin/alembic upgrade head
bash smoke_api.sh                           # ~55 checks against a running, demo-seeded server on :8000

# Frontend (Vite + React + TS + Tailwind v4)
cd frontend
npm install
npm run dev                                 # :5173, proxies /api -> :8000
npm run build                               # tsc -b && vite build (this is the type-check)
```

DB is controlled entirely by `DATABASE_URL` in `.env` (repo root): unset = SQLite file `backend/invtrack.db`; production = Supabase session-pooler string with the `postgresql+psycopg://` driver. Tests use in-memory SQLite via `tests/conftest.py`'s `db` fixture.

**Alembic gotcha:** autogenerated migrations render JSONB columns as `astext_type=Text()` without the `sa.` prefix — fix with `sed -i 's/astext_type=Text()/astext_type=sa.Text()/g'` on the new version file before `upgrade head`, then run `alembic check`.

## Architecture

### Backend (`backend/app/`)

Data flows bronze→gold: ingestion writes fact tables (each row keeps its `raw` source payload — that's the provenance layer), scoring reads facts and persists explainable score rows, routers serve CTE-based read models.

- **Ingestion** (`ingestion/`): one module per source. `runner.run_job()` wraps every source — records an `ingestion_run` audit row and swallows exceptions so **one broken source never blocks the others** (this failure-isolation pattern repeats at chamber, ticker, and filing level inside the sources; preserve it). All upserts are idempotent via natural keys. `http.py` provides the shared client with the SEC-required User-Agent (`SEC_EDGAR_USER_AGENT` env) and a global ~2 req/s throttle for all government sites.
- **Discovery universe** (`ingestion/targets.py`): `target_tickers(db)` = watchlist + top 25 tickers by recent congressional net buying. Fundamentals/prices/insider ingestion and scoring all iterate this, so Radar candidates get scores comparable to watchlist tickers. Congress trades are stored market-wide (not watchlist-filtered) — they ARE the discovery data.
- **Scoring** (`scoring/`): three components (fundamentals/congress/insider) each return `{score 0-100, source, data_as_of, inputs}` or `None`. `engine.compute_breakdown()` renormalizes weights across available components — a missing source is marked `"missing"` in the stored breakdown, **never a silent zero**. All weights/thresholds live in `backend/scoring.yaml` (also the `screener:` section) — deliberately user-tunable; don't hardcode.
- **Screener** (`screener.py`): 7 pass/fail criteria; missing data = status `"unknown"`, never a silent verdict. Same principle as scoring.
- **AI analysis** (`analysis/`): opt-in via `ANTHROPIC_API_KEY` (empty = feature disabled, 400 with setup hint). Fetches 10-K Items 1/1A/7 from EDGAR, single streamed Claude call (default `claude-opus-4-8`, adaptive thinking, no sampling params). Deliberately no RAG/vector DB. The model must never compute financial numbers — that's the structured pipeline's job. Reports cached per accession number in `ai_report`.
- **Read models** (`queries.py`): dashboard/ideas/stats queries are CTE-based SQLAlchemy (project preference). Must stay portable across SQLite and Postgres — no dialect-specific SQL outside the `JsonCol` variant in `models.py`.

### Data source reality (July 2026)

- **Senate**: scraped from the official `efdsearch.senate.gov` (`ingestion/senate_efd.py`) — CSRF/agreement handshake, paged DataTables JSON, per-report HTML tables parsed by *header name*, not column position. Paper filings skipped.
- **House**: the community Stock Watcher dataset is **defunct**; `HOUSE_DATA_URL` env accepts a mirror with the same row schema. House ingest erroring is expected and non-fatal.
- yfinance quirk: `debtToEquity` comes as a percentage (154.3 = 1.543×) — divide by 100 (see `fundamentals.snapshot_from_info`).

### Frontend (`frontend/src/`)

- Theming: CSS custom properties in `index.css` define validated palette roles (light + dark are separately chosen values, not auto-flipped), mapped to Tailwind utilities via `@theme inline` (`bg-surface`, `text-ink-2`, `border-hairline`, `var(--series-1..3)`, diverging `--div-pos/neg`). Use these roles, never raw hex. Component colors are fixed: fundamentals=series-1, congress=series-2, insider=series-3 (`COMPONENT_META` in `ComponentBars.tsx`); score polarity uses the diverging pair (≥60 bullish blue, ≤40 bearish red).
- Data: TanStack Query + typed fetch client in `api/client.ts`/`types.ts` — add new endpoints there, keep types mirroring the Pydantic schemas.
- Copy conventions: plain language, every score/signal explained where it appears (tooltips, `HowToRead`, breakdown views), and "not advice / lagging data" framing on anything signal-like.

### Testing conventions

Parsers are tested against recorded fixtures in `tests/fixtures/` (stock-watcher JSON, Form 4 XML, EFD search/PTR, 10-K HTML) — network calls never happen in tests. `app/demo.py` seeds synthetic data with dates generated **relative to today** so scoring windows always have data; when adding data-dependent features, extend the demo seed so the UI is verifiable offline and `smoke_api.sh` assertions hold.

## Environment note

In the Claude Code remote sandbox, outbound requests to data hosts (sec.gov, senate.gov, Yahoo) are blocked by the egress policy — develop against `seed-demo` + fixtures and let the user run live ingestion on their machine; iterate on the errors they paste back.
